How to check an email

  1. Start the API from the project folder with python run_api.py, then open this page at http://127.0.0.1:8000/ui/.
  2. On Analyse, paste the subject line and the body of the email. Leave out the headers: the model does not use them.
  3. Click Analyse email, or press Ctrl+Enter. The explanation takes a few seconds.
  4. Read the verdict first, then the highlighted words, to judge whether the reasons make sense for this email.

Reading the result

The verdict is a suggestion

The model assists triage: it does not decide. Treat a verdict whose highlighted words do not make sense as a reason to look closer, not as an answer.

Terms

Probability
How likely the model thinks the email is phishing, from 0 to 1.
Decision threshold
The probability at or above which an email is called phishing. It was chosen on validation data, never on the test set.
Weight
How much one word moved this prediction. Positive weights pushed towards phishing, negative towards legitimate.
LIME
The explanation method. It removes words at random, watches how the score changes, and fits a simple model to those changes. The weights describe this one email, not the model in general.
Placeholders
Links, email addresses and numbers are replaced by <url>, <email> and <num> before the model reads the text, so the highlighted text shows these instead of the originals.

If something goes wrong

  • "API offline" in the top card: the API is not running. Start it with python run_api.py and reload.
  • "model still loading": wait a few seconds; the badge updates on its own.
  • A message about the text being too long: the API states its own character limit; shorten the email to the body that matters.
